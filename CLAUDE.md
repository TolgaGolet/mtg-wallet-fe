# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

React 18 frontend (Create React App, plain JavaScript, no TypeScript) for [MTG Wallet BE](https://github.com/TolgaGolet/mtg-wallet-be), a Spring Boot personal-finance API (transactions, accounts, payees, categories, JWT auth with email verification and TOTP 2FA). UI is built with Mantine v7 and `@tabler/icons-react`. Deployed at https://mtgwallet.onrender.com.

## Commands

- `npm start` — dev server (react-scripts)
- `npm run build` — production build into `build/`. `CI=true npm run build` treats lint warnings as errors; there are no `eslint-disable` comments, so keep it that way (use `useApiQuery` / `useStableCallback` instead of suppressing `exhaustive-deps`). `package.json` adds `prefer-const` to the CRA config, so use `let` only for variables that are reassigned.
- `npm test` — Jest watch mode via react-scripts; single test: `npm test -- -t "name"` or `npm test -- path/to/file`; CI-style run: `CI=true npm test -- --watchAll=false`. Tests sit next to the code (`*.test.js`). `package.json` maps `axios` to its CJS build because CRA's Jest 27 can't load axios's ESM entry.
- `npm run format` / `npm run format:check` — Prettier (`.prettierrc`: es5 trailing commas) over `src/`.
- Linting is CRA's built-in ESLint (`react-app` config), surfaced during `start`/`build`.

## Configuration

All API endpoints come from `REACT_APP_*` env vars (base URL, login/refresh/logout/sign-up/verify-email paths, and the localStorage key for auth tokens). For local dev, copy `.env.example` to `.env`, which is gitignored. Production values live in Render's environment settings. CRA bakes these in at build time (they end up in the bundle, so never put secrets there), so restart the dev server after changing them.

## Architecture

- **Entry/providers** ([src/index.js](src/index.js)): `MantineProvider` (auto color scheme) → `Notifications` → `ModalsProvider` → `DatesProvider` (user's timezone, Monday first). `userTimezone` lives in [src/utils/timezone.js](src/utils/timezone.js) (not in `index.js`, so nothing imports the entry point).
- **Routing** ([src/App.js](src/App.js)): a single `createBrowserRouter` tree. The root route wraps `AuthProvider` + `RootLayout` (AppShell with nav). Authenticated pages are wrapped in `PrivateRoute`, which redirects to `/login` when `user` is absent. Every page except Home, Login and NotFound is `React.lazy`-loaded (its own chunk); `RootLayout` wraps the `<Outlet />` in `Suspense`, and the root route's `errorElement` ([RouteError](src/pages/RouteError.js)) catches render errors and chunks that fail to load after a deploy. The menu items come from one `NAV_ITEMS` list in [RootLayout](src/layouts/RootLayout.js), rendered as `NavLink`s (real links with `aria-current`).
- **Auth** ([src/context/AuthContext.js](src/context/AuthContext.js)): stores `{accessToken, refreshToken}` in localStorage; `user` is derived from the access token (never stored separately). Its functions return results instead of touching page state: `loginUser(credentials)` resolves to `{ status: "ok" | "totp" | "error", message, isEmailVerificationRequired }`, `signUpUser(data)` rejects on error, `logoutUser(message?)`. Pages own their loading/error UI; success dialogs use `openSuccessDialog`. After a successful login it calls `payee/create-defaults`. Tokens in localStorage are readable by any XSS: a known trade-off, to revisit in the security audit (httpOnly cookies need backend work).
- **API calls** ([src/api/client.js](src/api/client.js)): one module-level axios instance (60 s timeout, sized for Render cold starts). Pages get it through `const callApi = useAxios();` ([src/utils/useAxios.js](src/utils/useAxios.js)) and call `callApi.get/post/put/delete("resource/action", ...)` with paths relative to the base URL. `AuthProvider` hooks it up to React state through `configureAuth`. The client:
  - refreshes expired access tokens before requests and retries once on 401/403. All callers share one in-flight refresh, which is cleared when it settles. It logs out (once, while tokens are still stored) when the refresh token has expired or the refresh gets 401/403; network errors, 429 and 5xx (Render cold start) keep the session;
  - **shows the error toast itself**: the string body of an error response, a 429 message, or a network-error message (never for aborted requests). Callers don't add their own error toasts;
  - `publicApi` (same file) is the interceptor-free client for the public auth endpoints (login, sign-up, password reset, email verification, account recovery); there is no raw `fetch` in `src/`. Pass `{ silentErrors: true }` when a page shows the error itself, and use `getErrorMessage(error)` to read the server's text;
  - expected backend errors carry an `X-Error-Code` header (the backend's error constant name); read it with `getErrorCode` ([src/api/errorCodes.js](src/api/errorCodes.js)) instead of matching message text;
  - **sends top-level `Date` fields as local wall-clock strings** (`YYYY-MM-DDTHH:mm:ss`, via `toLocalDateTime` in [src/utils/dates.js](src/utils/dates.js)), because the backend stores `LocalDateTime` in the user's local time. Nested Date fields are not converted.
- **Loading data** ([src/utils/useApiQuery.js](src/utils/useApiQuery.js)): `useApiQuery((signal) => callApi.get(..., { signal }).then(r => r.data), [deps], { onSuccess })` returns `{ data, loading, error, retry }`. Always pass `signal`: the hook aborts stale requests when deps change or on unmount, so out-of-order responses can't win. Render `ListSkeleton` while loading and `<LoadError onRetry={retry} />` on error. Forms fill their values in `onSuccess`, not in an effect. For effects that should run only on certain values but read current state, wrap the handler in `useStableCallback` ([src/utils/useStableCallback.js](src/utils/useStableCallback.js)).
- **Validation** ([src/validation/rules.js](src/validation/rules.js)): every form rule (regexes, lengths, `LIMITS`, Mantine validators) lives here and mirrors the backend's request validation; `rules.test.js` pins the regexes to the backend strings, so a change must be made on both sides. Login and "confirm your password" fields only check that the password isn't empty (`requirePassword`).
- **Backend conventions**: listing is done with `POST <entity>/search` (body = filters, `params: { pageNo }`), and responses are Spring pages (`content`, `totalPages`, `totalElements`; use `totalElements` for limit checks). Single-entity fetches also use `search` with `{ id }`. Updates go to `PUT <entity>/update/:id` and deletes to `DELETE <entity>/delete/:id`.
- **Page patterns** ([src/pages/](src/pages/)): pages are grouped per entity folder. Form fields holding ids are named `...Id`, and requests are built explicitly with the fields the backend request class accepts. Create and edit share one component on route `<entity>/create-or-edit/:id`, where the literal id `create` means create mode (`isEdit = id !== "create"`). Forms use `@mantine/form` `useForm`. Accounts, Categories and Payees are thin wrappers around `PagedEntityList` (Accounts passes its own card via `renderItem`). The password checklist is `components/PasswordStrength`; validators all live in `src/validation/rules.js`. Confirmations and dialogs use `modals` from `@mantine/modals`. After a save, refetch what the page shows (`retry`) instead of `window.location.reload()`.
- **Shared components** ([src/components/](src/components/)): `showNotification(message, "success" | "error")` is the only way toasts are shown (it is rate-limited to 5 per 5s). `ClickableCard` is the clickable card for rows and list items (a link with `to`, otherwise a keyboard-operable button; always pass `aria-label`). `ListSkeleton` and `LoadError` cover loading and error states. `AmountInput` / `AmountFormatter` enforce 2-decimal, `.` decimal / `,` thousands formatting, and `AmountInput` is bound via `form` + `fieldName`. Enums such as `Currency` and `Interval` live in [src/enum/](src/enum/).
- **Accessibility**: clickable things must be real buttons or links (or `ClickableCard`), icon-only controls need an `aria-label`, and meaning can't rely on colour alone (amounts carry a +/− sign).
- **Styling**: Mantine props first; component-specific CSS goes in co-located `*.module.css` files. Hover and focus styles belong in CSS (`:hover`, `:focus-visible`), not in mouse handlers. PostCSS ([postcss.config.cjs](postcss.config.cjs)) provides `postcss-preset-mantine` and `$mantine-breakpoint-*` variables.
- **TransactionModal** ([src/components/TransactionModal/](src/components/TransactionModal/)): the create/edit transaction dialog used by Home, Transactions and Account Detail. Edit mode loads the transaction by id; `loadedRecentTransactions` only feeds the quick-pick suggestions (`suggestions.js`). `onSaved` tells the parent to refetch. Payee search lives in `usePayeeSearch`, and the request shape in `buildTransactionRequest` (`transactionRequest.js`).
- **Text and number helpers**: `includesIgnoringCase` / `sameName` ([src/utils/text.js](src/utils/text.js)) for case-insensitive matching (search folds with Turkish and browser-locale rules; `sameName` stays Turkish to match the backend), `formatAmount` / `accountOptionLabel` ([src/utils/format.js](src/utils/format.js)) for amounts in plain-text labels. Dates are displayed in the browser's locale.

## Related repos

- **Backend**: `../mtg-wallet-be` (Spring Boot 4 / Java 21, served under `/api` on `http://localhost:8080` locally). It has its own `CLAUDE.md` describing the controllers, DTOs, enums and error handling this app consumes.
- Changing what the UI sends or expects (fields, endpoint paths, enum `value`s, validation rules) usually needs a matching backend change. If the dev server origin changes, the backend's CORS allowlist (`SecurityParams.CORS_ALLOWED_ORIGINS`) must be updated too.
